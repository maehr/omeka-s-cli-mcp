Omeka S Client

An independent Python toolkit for the Omeka S REST API. It has a Python library, a CLI, and an MCP server. It reads and writes records, pages and filters lists, handles JSON-LD and files, and captures metadata snapshots.

Mode

Demo: seeded synthetic data in your browser. Writes change only this data. Live: read-only GET requests to an Omeka S installation, with optional API keys. CORS and server permissions apply.

Keys are optional. They let you read records that your Omeka user may see, including private ones. The playground sends only GET requests. The key itself is not read-only, because it carries its user's role. Use a key of a low-privilege user, for example the Researcher role. Keys travel as query parameters and appear in the server's access logs. The page keeps keys in memory only. The server must still allow CORS.

Read all pages of a collection into one list. Add filters to read fewer records. Verify checks the reads (see below).

Create a record from a JSON payload. Demo mode only. The new record exists only in this browser.

Change part of a record with a JSON payload. Demo mode only.

Delete a record by its ID. Demo mode only. You must confirm.

Create an item with one attached text file as media. Demo mode only.

Property condition (optional) Example: dcterms:identifier, eq, letter-001. Your Omeka S installation decides which types work. Demo mode supports only eq.
About Verify and Expected IDs

Verify reads the pages in ID order. It checks that the total count stays the same and that no ID repeats. At the end, the number of unique IDs must match the count. It tries up to three times.

Verify does not prove that you see every record, because permissions can hide records. It is not a point-in-time snapshot.

Expected IDs: if you fill this field, Verify turns on. The IDs that you get must equal this list. A missing ID or an extra ID makes the read fail.
